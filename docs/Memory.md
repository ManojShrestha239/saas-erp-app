## Architectural Decisions (Decision Log)

| #   | Decision                                                                                          | Reason                                     |
| --- | ------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 1   | Database-per-tenant on PostgreSQL, connection switched dynamically by `IdentifyTenant` middleware | Maximum isolation and security             |
| 2   | Money stored as integers (`integer('total_amount_cents')` → use BIGINT for new columns)           | No floating-point errors                   |
| 3   | Hybrid data flow: Inertia renders pages; typed API (`/api/v1`) for interactive data and mutations | Keeps `features/*/api` contract + SPA feel |
| 4   | Two named connections: `central` and `tenant`; no reliance on default connection                  | Prevents cross-tenant leakage              |
| 5   | Append-only stock movements + cached stock levels, updated in the same transaction                | Auditability + read speed                  |
| 6   | Automated module discovery via `SharedServiceProvider` and `ModuleServiceProvider` base class     | Zero-config module registration            |
| 7   | Central exception rendering via `ApiExceptionRenderer` in `bootstrap/app.php` and strict envelope | Uniform API contract without ad hoc errors |
| 8   | Tenants use ULID IDs and no soft deletes                                                          | Time-ordered B-tree indexing, URL-safe identifiers (security comes from authorization); lifecycle managed via `status` without unique constraint collisions |
| 9   | `IdentifyTenant` registered as alias only; resets context in `terminate()`                        | Explicit per-route tenancy assignment without leaking state across persistent cycles |
| 10  | Chart of Accounts seeder deferred to Phase 5                                                      | CoA structure requires the full Accounting module (accounts, hierarchies, system flags); premature seeding would couple provisioning to unbuilt code |
| 11  | Separate `pgsql_testing` database configured via `phpunit.xml` (`DB_DATABASE` / `DB_CENTRAL_DATABASE`) | Keeps test execution completely isolated from development database |
| 12  | Larastan level 8 + Pest Arch tests enforcing strict typing, no DB in controllers, module boundary isolation, no float in money | Static and architectural guarantees enforced in CI |
| 13  | Provisioning database user requires only `CREATEDB` privilege in production (tied to Phase 7 deployment checklist) | Prevents superuser exposure and enforces least privilege; database creation succeeds without granting full administrative privileges; verification of dedicated non-superuser role added to Phase 7 release checklist |
| 14  | Tenant-scoped session auth: host-only cookie (`SESSION_DOMAIN=null`), `web` guard resolves `tenant_users` via `UsesTenantConnection`, `tenant_id` session binding with `EnsureTenantSession` rejecting cross-tenant sessions | Defense-in-depth against cross-tenant session hijacking; browser enforces origin separation; middleware guarantees session validity across subdomains |
| 15  | Password reset tokens and email verification tokens hashed (SHA-256) in tenant DB; defaults: 60-minute token expiry, email verification required before login for tenant users (`auth.require_email_verification`), password reset revokes all active sessions across the session driver store, and mail is logged to file in development (`MAIL_MAILER=log`). | High entropy single-use tokens prevent token theft and replay; cross-device session destruction terminates active access upon credential changes; development file logging prevents accidental dispatch. |
| 16  | Tenant-isolated Spatie RBAC: `TenantPermissionRegistrar` isolates cache by tenant ID (`spatie.permission.cache:{tenant_id}`); `TenantUser`, `Role`, and `Permission` use `UsesTenantConnection`; pivot `model_id` uses string(36) for ULIDs. | Guarantees zero cross-tenant role/permission leakage across concurrent requests or multi-tenant background commands; preserves ULID model identity; aligns with database-per-tenant architecture. |
| 17  | Subscription package limits queried via `TenantPackageService` on `central` connection, enforced at business mutation time via `EnforceUserLimitService`; deactivated user status enforced in both login and `EnsureTenantSession`. | Cross-module decoupling compliant with Arch tests, while guaranteeing defense-in-depth against unauthorized access or limit violations. |
| 18  | Google OAuth verified-email account linking: `oauth_accounts` table in tenant DB tracks provider identities per tenant; `GoogleAuthService` enforces strict `email_verified === true` (rejects unverified Google emails with 403 `UNVERIFIED_OAUTH_EMAIL`), requires existing tenant user (rejects uninvited/unknown users with 404 `ACCOUNT_NOT_FOUND`), blocks deactivated accounts (403 `ACCOUNT_DEACTIVATED`), and auto-verifies unverified tenant email on verified Google OAuth match. | Guarantees zero account takeovers from unverified OAuth emails, blocks unauthorized tenant registration into private tenant ERPs, preserves database-per-tenant isolation, and fulfills PRD §3.2. |
| 19  | Central Super Admin authentication: `Modules\SuperAdmin\Models\SuperAdmin` explicitly bound to `central` connection, dedicated `super_admin` auth guard and provider in `config/auth.php`; `EnsureCentralDomain` restricts routes strictly to central domain (`nexuserp.test`, `localhost`, `127.0.0.1`) rejecting tenant subdomains with 404 `ROUTE_NOT_FOUND`. | Guarantees complete isolation between platform administration and tenant data, prevents credential collision or impersonation, and ensures Super Admin attack surface is invisible on tenant domains. |
| 20  | Inertia frontend auth pages & lazy props: Inertia root view `app.blade.php` and `HandleInertiaRequests` middleware lazy-evaluates `auth.user` and `tenant` via Closures after `identify.tenant` route middleware sets `TenantContext`; client-side RBAC enforced via `useCan` hook and `<Can>` wrapper component checking both permissions and roles case-insensitively; full sidebar navigation filtered by `useCan`. | Guarantees tenant context and active tenant connection are cleanly resolved before props are shared; prevents concrete model coupling in `Shared/` (preserving Arch tests); ensures granular client-side permission-gated navigation and actions. |
| 21  | Product catalog architecture in `Modules\Inventory`: integer-cent money fields (`cost_price_cents`, `selling_price_cents` as `BIGINT`), tenant-scoped unique SKU, ULID IDs, forward-only tenant migrations dynamically discovered in `ProvisionTenantDatabase`, and strict RBAC policy checks against `products.view` and `products.manage`. | Guarantees zero floating-point inaccuracies, strict tenant isolation and ULID performance; ensures dynamic execution of module migrations during provisioning without manual array maintenance; enforces RBAC matrix per PRD §2.1. |
| 22  | Stock engine architecture in `Modules\Inventory`: append-only `stock_movements` table (`created_at` only, no `updated_at`), cached `stock_levels` table (`[warehouse_id, product_id]` compound unique constraint), updated atomically inside `DB::transaction(..., 3)` with pessimistic row-locking (`lockForUpdate()`), and negative stock prevention enforced server-side against tenant setting `allow_negative_stock`. | Concurrency-safe inventory balances without race conditions; immutable audit trail of all quantity deltas; rapid O(1) cached reads for on-hand and available levels; strict adherence to PRD §3.4 acceptance criteria. |
| 23  | Manual stock adjustments architecture in `Modules\Inventory`: header-line pattern (`stock_adjustments` + `stock_adjustment_items`), atomic sync with `stock_movements` and `stock_levels` via `StockService`, sequential document numbers (`ADJ-YYYY-000001`), line and total cost impact tracking in minor units (`*_cents` BIGINT), mandatory reasons, and decoupled `StockAdjusted` domain event for Phase 5 General Ledger posting. | Ensures auditability, financial accuracy without floats, pessimistic concurrency safety, and seamless accounting integration when Phase 5 GL posting is enabled. |
| 24  | Contacts module architecture in `Modules\Contacts`: unified `contacts` table with `type` enum (`customer`, `supplier`, `both`) to support commercial partners acting as both client and vendor without data duplication; sequential code generation (`CUST-*`, `SUPP-*`, `CONT-*`); minor units for financial bounds (`credit_limit_cents`, `opening_balance_cents` as `BIGINT`); jsonb address payloads; granular RBAC checks differentiating sales reps (customers only) and procurement/accountants (suppliers/both). | Prevents data duplication for dual-role entities, guarantees strict financial bounds without floating-point math, and preserves multi-tenant data isolation and RBAC. |
| 25  | Reusable headless DataTable built on `@tanstack/react-table` (v8) with server-side/client-side hybrid controls, density toggles (compact 40px / comfortable 52px), column visibility, sticky headers on `surface-muted`, skeleton loading states, designed empty states with CTA, and accessible dropdown menus. | Guarantees high-density ERP data presentation, strict TypeScript typing (no `any`), consistent Design.md tokens, and seamless server pagination integration across all subsequent modules. |
| 26  | Low-stock detection and real-time SSE stream architecture: `LowStockDetected` event dispatched inside `StockService::recordMovement` via `ShouldDispatchAfterCommit`; listener pushes event payload to Redis channel `tenant:{tenant_id}:stream`; `/api/v1/stream` endpoint streams `text/event-stream` with heartbeat ticks; frontend `useEventStream` manages lifecycle and updates `LowStockTable` live. | Zero polling overhead, decoupled post-commit broadcasting, resilient auto-reconnecting browser streams, and instant shortage visibility for warehouse managers and owners without page reloads. |
| 27  | Asynchronous queued CSV import engine: forward-only `csv_imports` table in tenant DB tracks status, row metrics, and line-by-line validation errors; queued jobs `ProcessProductCsvImportJob` and `ProcessContactCsvImportJob` execute within tenant context; endpoints return `202 Accepted` immediately for poll-based UI; `MoneyParser::toCents` parses financial amounts to integer cents with zero floats; configurable duplicate resolution (`skip` vs `update`); reusable frontend `CsvImportDialog`. | Prevents HTTP timeouts on large datasets; prevents floating-point corruption in pricing/balances; provides immediate UX feedback with progress percentage and actionable error reports; adheres to tenant isolation and RBAC. |
| 28  | Gap-free per-tenant document numbering engine in `Shared\Services\DocumentNumberingService`: forward-only `document_sequences` table in tenant DB (`[type, year]` compound unique index, `BIGINT current_number`); atomic increment under `lockForUpdate()` inside `DB::connection('tenant')->transaction(..., 3)`; non-locking preview (`peekNext`); manual sequence jumping (`setNextNumber`); gap-free transaction rollback preservation; backed enum `DocumentType` with standard prefixes (`INV`, `QUO`, `PO`, `GRN`, `BILL`, `REC`, `PAY`, `ADJ`, `CN`, `DN`, `JRN`). | Concurrency-safe, legal/tax-compliant gap-free document numbering without race conditions across all purchasing, sales, inventory, and accounting document sequences; maintains strict multi-tenant isolation. |
